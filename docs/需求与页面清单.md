# V0.1｜需求与页面清单

版本：V0.1（设计草案）　日期：2026-10-28　状态：**进行中，待评审**

## 1. 项目边界（已确定的开发基线）

- 总站建设：校园数字教学资源中心；首期唯一可用模块为「书法教学」。
- 素材范围：一年级至五年级**下册**、每年级第 2–14 周，共 65 个周次、741 个 MP4、总量约 1.6 GB（均来自前期目录统计，尚未现场核验视频文件）。
- 教材二维码应直达指定周次或单课，不必绕经主站。
- 学生、家长无需登录；**电脑端与手机端同时适配**，并优先保证手机微信内置浏览器的播放与触控体验。
- Vue3 + TypeScript + Vite + Vue Router；JSON/TS 课程索引 + 原生 HTML5 video；未来视频拟通过腾讯云 COS 提供。
- 本期不做账号、数据库、管理后台、打卡积分、书法评分、其他课程模块的实际内容。

> 注意：以上是项目团队采用的规划基线，不代表学校已经逐项签字确认。学校名称、域名、印刷粒度及素材公开许可均待核实。

## 2. 访问流程

### A. 教材按周扫码（主流程，是否采用待学校确认）

教材中的「一年级下册·第 2 周」二维码
→ `/calligraphy/grade/1/week/2`
→ 看到「第 2 周·长撇」、6 个示范视频列表和当前视频播放器
→ 点击播放/暂停/重播，或点列表中的其他笔画与汉字进行切换。

### B. 教材按单个字/笔画扫码（兼容流程，是否采用待学校确认）

某示范字二维码
→ `/calligraphy/grade/1/week/2/lesson/1`
→ 进入同一套播放页面，自动选择指定课程（示例是“长撇”）
→ 仍能切换本周其他课程；回退到年级、周次列表。

**禁止**：把二维码直接指向 COS MP4 链接；正式学校域名未确定前不能印刷最终二维码。

### C. 自主浏览（无二维码）

`/` 总站首页 → `/calligraphy` 年级入口 → `/calligraphy/grade/1` 第 2–14 周列表 → `/calligraphy/grade/1/week/2` 视频播放。

## 3. 站点信息架构

```text
/                         校园数字教学资源中心（总站）
└── /calligraphy           书法教学首页（1–5 年级下册入口）
    ├── /grade/1           一年级下册（第 2–14 周）
    │   ├── /week/2        第 2 周（视频播放器 + 6 个课程）
    │   └── /week/2/lesson/1   第 2 周第 1 节（同一播放器页面，预选课程）
    ├── /grade/2           二年级下册
    ├── /grade/3           三年级下册
    ├── /grade/4           四年级下册
    └── /grade/5           五年级下册

*                         404 / 暂无资源（明确给出返回入口）
```

`/reading`、`/science`、`/materials` 等未来模块仅属于架构扩展设想，V0.1 不创建可访问的空模块页面。

## 4. 页面清单及电脑/手机双端关键内容

| 页面模板 | 路由 | 主要信息/组件 | 核心交互 |
|---|---|---|---|
| P1 总站首页 | `/` | 学校名称/中性占位标识、站点介绍、已开放的书法教学入口 | 进入书法模块 |
| P2 书法首页 | `/calligraphy` | 标题、学习提示、1–5 年级下册卡片 | 选择年级 |
| P3 年级周次页 | `/calligraphy/grade/:grade` | 当前年级、面包屑、第 2–14 周按数值排序的入口；可显示已确认主题 | 选择周次 |
| P4 周次播放页 | `/calligraphy/grade/:grade/week/:week` | 周次主题、课程标题、原生视频区域、6 或 15 个课程按钮、错误/加载提示、返回周次 | 播放、暂停、重播、切换 |
| P4 的单课入口 | `/calligraphy/grade/:grade/week/:week/lesson/:lessonKey` | 复用 P4，不额外建设重复页面；指定课程预选 | 直接播放目标课（遵守浏览器自动播放限制） |
| P5 404/缺失资源 | 不匹配/不存在的路由 | 明确错误、返回总站/年级 | 恢复访问 |

**设计选择：**周次页即播放页，避免学生扫码后又多点一次才能看到视频；单课链接仅是播放器的预选状态。自动播放不作为验收要求，微信/iOS 的用户手势限制应被尊重。

## 5. 双端响应式设计原则

1. 采用一套网站自适应桌面、平板和手机，不维护独立电脑版与手机版。桌面端重点验证 1280–1440px，移动端重点验证 360–430px；主要触控按钮约 44px 或更高。
2. 电脑端播放页采用播放器在左、课程列表在右的双栏结构；手机端改为播放器在上、课程列表在下，周次名称和当前课程标题清晰可见。
3. 电脑端年级/周次内容可采用多列网格，手机端卡片改为双列或单列；视频竖屏/横屏实际比例不确定，使用原生播放器适配原始宽高，不裁剪关键笔画内容。
4. 不预设每一课的时长、分辨率或封面：这些须在真实 MP4 检测后决定。
5. 每个页面提供「回书法首页 / 返回年级」导航；微信直接扫码进入也能辨认当前所在位置。
6. 缺文件/加载失败时展示可理解的错误，保留课程标题及切换其他课程的能力。
7. 首期暂不做搜索、登录、收藏、成绩、推荐等非核心功能。

4. 桌面与移动端共享数据、课程路由及二维码 URL，窗口大小变化不导致跳转到另一套网址。

5. 响应式规则与各端验收宽度详见 `docs/双端响应式设计与验收规范.md`。
